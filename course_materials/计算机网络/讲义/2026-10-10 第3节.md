# 计算机网络｜2026-10-10 第3节

本节从 05:20 开始第四章网络层，讲网络层服务模型、IP 配套协议、直接交付与间接交付、IPv4 分类地址、特殊地址、接口地址及子网划分。01:52–05:12 为课堂点名，51:12 后主要是休息与零散交谈。讲义中的补充算例用于解释规则，课堂投影中未被转写记录的具体 IP 地址不予补写。

## 网络层的两种服务思路（05:20–09:27）

### 可靠性交给网络或端系统

教师在 05:20 明确进入第四章，说明本章主要关注网际协议 IP 和路由选择协议，后面还会介绍多播、VPN、MPLS 等专题。课堂先比较两种网络服务思路：一种由网络内部建立逻辑连接并管理沿途资源，另一种让网络提供无连接的数据报交付，由端系统处理需要的可靠性（06:12–09:09）。这项比较是理解 Internet 网络层定位的起点。

面向连接的虚电路服务会在发送数据前建立沿途状态，转发设备按虚电路标识处理分组。事先建立状态可以支持资源安排及服务质量设计，但可靠交付仍需要相应的差错处理和重传机制；仅有“建立虚电路”并不能自动保证分组永不丢失。课堂把这种思路与电信网络经验联系起来（06:40–07:24）。虚电路是逻辑连接，同一物理链路仍可能同时承载多个逻辑连接。

Internet 的 IP 数据报服务采用无连接、尽最大努力交付：每个数据报携带转发所需的目的地址，路由器按当前转发表选择下一跳；网络层不承诺到达、不承诺顺序，也不承诺固定时延（07:27–09:27）。因此丢失、重复及乱序都可能出现。若应用要求可靠字节传送，可由端系统使用相应的运输层协议及应用机制处理确认、重传、流量控制和拥塞控制。具体端到端可靠性仍取决于所采用的协议与实现，不能因为使用 IP 就推断所有业务均由 TCP 承载。

| 对比对象 | 虚电路服务的典型做法 | IP 数据报服务的典型做法 |
| --- | --- | --- |
| 发送前准备 | 建立逻辑连接与中间设备状态 | 每个数据报独立提交 |
| 转发依据 | 已建立连接的标识与状态 | 目的 IP 地址及转发表 |
| 分组路径 | 通常沿已建立路径 | 可因路由变化选择不同路径 |
| 可靠性 | 可结合网络内部控制机制提供 | IP 本身只提供尽力交付，端系统按需补足 |
| 设备状态 | 中间设备保存连接相关状态 | 核心转发主要依赖路由和邻接信息 |

补充情境：主机 A 连续发送编号 1、2、3 的三个 IP 数据报，路径上的路由调整可能使 2 先于 1 到达，3 也可能因拥塞被丢弃。IP 的目标是按照已有路由尽力传递各个报文；接收应用若要求原顺序及完整数据，必须依赖提供对应能力的更高层机制。路由器只对一个数据报作转发，并不代表它已为整个应用会话保留了资源。

## IP 与配套协议、互联设备（09:27–13:51）

教师介绍 IPv4 网络层涉及的 IP、ARP、ICMP 和 IGMP（09:27–12:09）。IP 负责数据报地址与转发；ARP 用于在同一 IPv4 链路上根据目标 IPv4 地址取得相应链路层地址；ICMP 用于差错报告和网络诊断，`ping` 通常使用 ICMP Echo；IGMP 处理 IPv4 多播组成员关系。它们服务于不同问题，不能把 ARP 当成跨互联网逐跳寻找最终主机的路由协议。

补充说明：主机发往异地网络时，先选择下一跳路由器的 IP 地址，随后在当前以太网链路上解析下一跳的 MAC 地址；IP 数据报的最终目的地址仍指向远端主机。若目的主机就在本地链路，则解析本地主机的 MAC 地址。ARP 请求通常只在当前广播范围内工作，路由器不会将它当作普通 IP 分组逐跳传递。ICMP 与 IGMP 的报文承载及层次关系按具体协议理解；课堂把它们作为 IP 的配套协议介绍（10:09–12:09）。

课堂按处理层次回顾互联设备（12:15–13:23）：物理层的中继器和集线器处理信号；链路层的网桥与交换机依据 MAC 地址处理帧；网络层的路由器依据 IP 地址及路由信息处理数据报；更高层的网关可能转换更复杂的协议或应用语义。设备名称不能完全取代功能判断，例如某些交换设备还具备网络层转发能力；课堂这一分类用于识别设备在题目中主要承担的功能。

“异构网络互联”意味着互联的链路可能采用不同介质和帧格式。IP 数据报可以穿过多种链路技术，每到一个新的链路都由相应链路层重新封装。路由器处理的是目的网络与下一跳，不能依赖某段以太网帧从源主机完整穿越所有路由器。教师表示虚拟互联的一些定义不作为本节重点，并在 13:51 转入直接与间接交付。

## 间接交付、直接交付与逐跳封装（13:51–15:36）

教师用路径图说明：数据报尚未进入目的主机所在网络时，经过路由器向下一跳转发属于间接交付；已经位于目的主机所在链路、能够把数据报送到最终目的主机时，属于直接交付（13:51–14:55）。中间路由器根据目的 IP 地址和路由表决定转发方向；最后一个链路仍要把 IP 数据报放入该链路的帧中。若是以太网，发送接口通常需要知道最终接收接口的 MAC 地址（14:55–15:11）。

补充路径：A 位于网络 X，B 位于网络 Z，中间经过 R1、R2。A 首先按照自己的地址与掩码判断 B 是否位于本地网络。由于不在本地，A 将目的 IP 仍为 B 的数据报交给默认网关 R1；A→R1 的以太网帧目的 MAC 是 R1 的本地接口。R1 和 R2 分别选择下一跳，再根据各自出口所在链路重新封装。最后，连接网络 Z 的路由器把目的 IP 为 B 的数据报装入发往 B 的本地帧。每段帧的源、目的 MAC 可改变，最终目的 IP 地址在普通转发过程中保持指向 B；若存在 NAT 等额外机制，IP 地址可能按其规则改变。

由此可以回答两个经常混淆的问题。第一，路由器查询的是“到目的网络应走哪个出口或下一跳”，接入目的网络后仍须完成链路层送达。第二，直接交付也需要先用 IP 地址判断目标，再使用链路层规则发送帧。课堂简述“前面用 IP，最后用 MAC”用于强调最后一段的具体传输，不能理解为最后一段完全不再使用 IP 地址。

## IPv4 地址的分类结构与形成背景（15:36–25:37）

### 32 bit 地址与接口位置

教师按分类地址、划分子网、无分类编址的顺序介绍 IPv4 地址结构的演变（15:36–16:34）。IPv4 地址长 32 bit。早期分类地址把前一部分作为网络号，后一部分作为主机号；划分子网从原主机号中借出部分位；无分类编址用前缀长度描述网络范围。当前网络常使用前缀表达，学习分类地址仍有助于理解地址历史、网络规模与掩码的作用。

IP 地址跟接口接入的网络相关（16:34–18:24）。同一笔记本在教室与家里接入不同网络时，可以取得不同地址；同一设备同时使用有线与无线接口时，也可分别配置地址。路由器至少连接两个网络，在课堂常见模型中每个参与 IP 转发的接口位于各自对应的网络。实际设备还可能有环回接口、隧道或未编号链路，因此不能用“设备数量”直接推算 IP 地址数量。

### A、B、C 类地址的前缀

分类地址以开头比特识别类型（19:25–22:23）：A 类以 `0` 开头，网络号占 8 bit，主机号占 24 bit；B 类以 `10` 开头，网络号占 16 bit，主机号占 16 bit；C 类以 `110` 开头，网络号占 24 bit，主机号占 8 bit。D 类 `1110` 用于多播地址范围，E 类 `1111` 为特殊保留范围。本节围绕常规单播网络主要讨论 A、B、C 三类。分类是历史分配方法，今天判定实际子网范围还要看前缀长度或子网掩码。

| 类别 | 固定开头 | 历史默认网络号长度 | 默认主机号长度 | 传统网络内一般可用主机地址数 |
| --- | --- | --- | --- | --- |
| A | `0` | 8 bit | 24 bit | $2^{24}-2=16,777,214$ |
| B | `10` | 16 bit | 16 bit | $2^{16}-2=65,534$ |
| C | `110` | 24 bit | 8 bit | $2^8-2=254$ |

表中“减 2”对应历史常规子网中主机部分全 0 的网络地址与全 1 的定向广播地址；特殊点到点前缀及具体协议例外需要单独判断。A 类第一字节通常讨论 1–126；`0/8` 有特殊用途，`127/8` 保留给环回。B 类第一字节范围为 128–191，C 类为 192–223。一个点分十进制字节最大为 255，因此包含 256 的表达无效。课堂投影的例题地址没有完整写入字幕，讲义采用自拟地址演示规则。

教师用学校历史地址申请说明固定类别的缺陷（23:11–25:37）。一个 C 类网络只有 254 个常规主机地址，较大的单位可能需要取得多个 C 类网络；若这些网络地址彼此不连续，其他路由器难以用一条共同前缀路由表示全部范围。反过来，直接取得 B 类地址又可能留下大量未使用地址。分类地址由此造成地址使用和路由表规模方面的问题。课堂口述的学校历史申请数量属于教师举例，不作为当前校园网络地址资源的事实判断。

补充说明：假设某机构需要 500 个地址，单个传统 C 类网络的 254 个常规主机地址不足，至少需要两个；若使用一个传统 B 类网络，则可容纳 65,534 个常规主机地址，利用率很低。无分类编址和子网划分通过允许更灵活的前缀长度缓解这种固定颗粒度的问题。具体申请规模还会考虑冗余、广播范围、未来扩展与分配政策，不能只用当前主机数作唯一依据。

## 点分十进制与特殊 IPv4 地址（25:37–28:11）

IPv4 的 32 bit 通常分成四组，每组 8 bit，以点分十进制写出，例如 `192.0.2.17`。每组取值在 0–255 之间，因为 $2^8=256$ 个不同值，从 0 计数到 255（25:37–26:07）。地址写法合法不代表它一定是可分配给普通主机的单播地址，还须检查保留用途、网络地址和广播地址。

教师介绍若干特殊地址（26:32–28:11）。`0.0.0.0` 在主机尚未获得正常 IPv4 地址等特定场景可作为源地址，不能把它当作普通远端目的主机地址。全 1 地址 `255.255.255.255` 是受限广播地址，发送到本地链路；一个具体网络前缀下主机位全 1 的地址属于该网络的定向广播地址，能否跨路由转发还受设备策略约束。`127.0.0.0/8` 用于本机环回，常见 `127.0.0.1`；向环回地址发送通常由本机协议处理，不经普通外部链路发送。

补充演算：地址 `192.0.2.17/24` 的网络位是前 24 bit，主机位是最后 8 bit。按位与掩码 `255.255.255.0` 后得到网络地址 `192.0.2.0`；主机位全 1 得到该网段的定向广播地址 `192.0.2.255`。`192.0.2.17` 可用来表示一个接口，但仍需确认网络配置与具体分配。`192.0.2.0/24` 是用于文档示例的地址段，此处只作为计算样例。

用地址做软件回环测试时，测试的是本机 IP 处理与应用监听等相关部分，不能证明外部网线、交换机、默认网关或远端服务器通畅。若本机 `ping 127.0.0.1` 成功而远端访问失败，还需要继续检查接口地址、链路连通及路由等信息。

## IP 地址属于接口及网络划分（34:41–46:12）

### 分级地址对路由表的作用

网络号与主机号分级，允许地址分配机构把网络范围交给单位，再由单位分配内部接口地址（34:41–35:07）。中间路由器也可只保留到目的网络的路由，不必为该网络中每台主机分别建立一条独立的全网路由（35:07–35:57）。例如一个 `/24` 网络中有 100 个终端，远端路由器可以用指向该 `/24` 的一条前缀路由表示到达范围；到了目的网络附近，设备再依据更具体信息交付。

教师再次强调 IPv4 地址对应接入某个网络的接口（35:57–37:20）。若笔记本有两个同时启用的接口，可分别拥有不同地址；路由器连接多个网络，通常每个参与 IP 的接口有其地址。地址的网络部分必须与接口所连接的网段配置一致，才能按一般的同网段规则通信。判定两个接口能否直接通信时，应使用地址与对应掩码计算其网络范围，并考虑链路配置。

物理层中继器、集线器及普通二层网桥、交换机可以在同一 IP 子网内连接多个接口；路由器连接不同网络时，需要按路由与各接口地址处理（37:24–38:11）。课堂给出图示，要求数出不同网络号，口述答案为六个网络（38:44–39:50）。图中完整地址与连接图形没有出现在转写中，因此讲义只保留“按网络号与路由器接口判别”的方法，不画未经核实的拓扑。

课堂还引出无编号点到点链路：某些路由器之间的点到点连接可不在该连接上另配独立 IPv4 地址，而借用其他接口地址完成特定配置（40:39–46:12）。这属于具体设备功能与路由配置的组合，并非任意以太网接口都可以省略地址。教师说明所展示的例子来自另一本书，只要求了解，未要求记忆配置命令（43:26–45:52）。课堂口述的“串口、主网、子网掩码”条件与投影配置缺少完整对应图，执行实际配置时应以设备文档及实验指导为准。

补充说明：无编号接口的关键目的在于减少点到点链路占用的 IPv4 地址，并让路由器仍能通过该链路转发。接口能否使用无编号配置，由设备、操作系统、链路协议、邻接及路由要求共同决定。它不改变 IPv4 数据报目的地址的意义，也不能用来替代多接入以太网中普通接口地址规划。

## 子网号从主机位借取与子网掩码（46:12–51:12）

分类地址的 A、B 类网络范围较大，内部若按一个整体管理，地址利用、故障范围和路由安排都不便。教师介绍划分子网的历史思路：IPv4 地址仍是 32 bit，从原主机号的高位借出若干 bit 作为子网号，形成“原网络号、子网号、主机号”三部分（46:12–47:44）。借位后没有增加总地址位数，子网数量增多，同时每个子网可用的主机地址数量减少。

例如一个历史 B 类网络原先使用 `/16`，若再借 8 bit 作为子网号，内部每个子网成为 `/24`。原来一个网络理论上有 $2^{16}$ 个主机号组合；划分后理论上有 $2^8=256$ 个子网编号，每个子网剩 $2^8=256$ 个地址组合。按照普通 `/24` 子网规则，每个子网有 254 个常规可分配地址。子网编号与可用数量还会受历史规则和具体前缀政策影响，答题须看题目所采用的约定。

内部子网划分后，外部网络仍可能按汇总前缀把数据发到该单位边界路由器；进入单位内部，再按目的地址所属子网继续选择路径（47:44–49:34）。这样能分层管理大范围地址，同时缩小各个广播范围。直接交付仍发生在目的主机所属的最终链路；不能因为增加子网号，就认为所有路由器都需要保存每台主机的 MAC 地址。

子网掩码也长 32 bit，左侧连续的 1 对应网络前缀，右侧连续的 0 对应主机部分（49:34–50:58）。例如 `/24` 的掩码为 `255.255.255.0`，二进制有 24 个连续的 1。前缀长度无须是 8 的整数倍，例如 `/27` 的掩码为 `255.255.255.224`；其最后一个字节 `11100000`，前三 bit 属于网络前缀，后五 bit 属于主机部分。

补充计算：给出 `192.0.2.77/27`，最后一字节 `77` 与掩码 `224` 按位与得到 `64`，所以网络地址为 `192.0.2.64`。后五位共有 $2^5=32$ 个地址，地址范围是 `192.0.2.64` 至 `192.0.2.95`；在常规子网语境下，主机地址范围为 `192.0.2.65` 至 `192.0.2.94`。同一结果也可用块大小 $256-224=32$ 快速判断：77 位于从 64 开始的那个 32 地址区间。掌握按位与能应对非整字节前缀，块大小方法可以复核结果。

**【理解重点】地址与掩码须一起使用。**单看 `192.0.2.77` 不能确定其实际子网大小；当掩码改成 `/26` 时，所在子网范围变为 64 个地址，广播地址与可分配数量也随之改变。教师在 50:25–50:58 强调掩码的连续 1 不要求停在字节边界。第四章后续计算将继续使用这一点。
