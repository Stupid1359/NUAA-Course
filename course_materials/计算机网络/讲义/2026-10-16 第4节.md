## RIP v1 与 RIP v2 的差异（03:31–06:15）

教师首先比较 RIP 的两个版本。课堂列出三点：RIP v2 支持鉴别机制，更新消息使用多播，路由条目携带子网掩码；RIP v1 的课堂描述分别是缺少相应鉴别、使用广播，以及不携带子网掩码（03:36–06:15）。这三个差异服务于三个不同问题：确认更新来源、控制接收范围、表达子网前缀。答题时要分别解释用途，不能只背“v2 比 v1 新”。

**【理解重点】RIP v1 所说的广播限于发送接口所在的本地网络。**教师特别说明，主机与路由器共享该网络时，广播更新可能被同网段的普通主机接收；它不会凭一份广播报文自动送到整个互联网（04:28–05:42）。路由器分隔网络，在一个接口看到的本地广播与其他接口所连网络的广播范围不同。RIP v2 使用面向运行 RIP 的设备的多播组，减少普通主机接收无关更新的情况（05:42–05:57）。多播是否被网络设备正确转发，还取决于接口与协议配置。

RIP v2 条目带子网掩码意味着接收方可以按前缀长度解释目的网络。例如 `192.0.2.0/26` 与 `192.0.2.64/26` 可以分别表示两段不同网络；只传递一个传统的有类网络地址，无法完整表达这类划分。鉴别功能用于减少未经授权的更新被接受的风险，不过具体强度取决于所用鉴别方式与密钥管理，课堂没有要求推导鉴别报文字段。

| 比较项目 | RIP v1 的课堂描述 | RIP v2 的课堂描述 | 处理的问题 |
| --- | --- | --- | --- |
| 更新接收方式 | 本地广播 | 多播组 | 控制同一网络内谁接收更新 |
| 子网信息 | 不携带掩码 | 携带掩码 | 描述具体前缀 |
| 来源鉴别 | 缺少课堂所述机制 | 支持鉴别 | 降低伪造更新的风险 |

## RIP 更新报文的封装与字段（06:15–08:57）

RIP 更新消息由 UDP 承载，再作为 IP 数据报发送（06:15–06:45）。层次关系可写为 `IP 数据报 → UDP 报文 → RIP 消息`，箭头表示外层承载内层。路由器在网络层转发 IP 数据报，运行 RIP 的进程处理 UDP 负载中的更新。把 RIP 称为“路由选择协议”，描述的是其用途；其更新报文经 UDP 传输，描述的是封装方式，两者能够同时成立。

RIP 消息有首部和一组路由条目。教师说明首部包含命令、版本和保留字段，每条路由记录占 20 B；条目内有地址族、目的网络、子网掩码、下一跳与度量等信息（06:46–08:49）。目的网络确定“到哪里”，子网掩码界定网络范围，度量表示距离。下一跳字段帮助说明如何转发，但把收到的邻居通告用于本地路由表时，仍须按上一节的计算规则确定本地实际下一跳。

课堂强调一份更新消息能承载的条目数量有限，超过容量时发送多份消息（06:53–08:20）。教师把容量设计与早期 IPv4 最小重组要求及分片风险联系起来：控制消息保持较短，可以降低需要 IP 分片的机会。分析时不要把“单份消息最多装多少条”误读成“整个路由器只允许存多少条”。路由器能存储的前缀与一次 UDP 报文能装载的前缀属于不同容量。

补充计算：若首部占 4 B，每个路由条目占 20 B，装入 25 条时 RIP 内容为 $4+25\times20=504$ B；再加 UDP 首部 8 B 和无选项 IPv4 首部 20 B，得到 532 B。这个算式说明课堂所说“约 500 B”的量级，也解释了为何单份更新适合保持在较小的 IP 数据报内。实际是否发生分片还要看出口链路 MTU、IP 首部选项及实际封装，不能从 532 B 直接推断所有路径都不会分片。鉴别条目可能占用一个路由条目的位置；具体可放条数应按题目指定的消息结构核算。

## RIP 的坏消息传播与计数到无穷（08:57–15:03）

教师用三个网络和两个路由器的连接解释“好消息传播快、坏消息传播慢”（08:57–10:11）。正常时，R1 直连网络 N1，课堂约定直连距离为 1；R2 从 R1 学到 N1，距离为 2。若 N1 的链路故障，R1 知道 N1 不可达，把度量记为 16。R2 此时若尚未收到故障消息，仍保留旧记录“经 R1 到 N1，距离 2”（10:12–10:52）。

关键事件发生在更新不同步时：R2 把旧记录通告给 R1，R1 误以为 R2 另有到 N1 的路径，计算“经 R2 到 N1，距离 3”；R1 后续又把 3 通告给 R2，R2 计算出 4。两个路由器可能不断互相引用旧信息，度量逐轮增加，直至达到 RIP 定义的不可达值 16（10:53–12:10）。这就是计数到无穷问题。这里的“无穷”是 RIP 的有限上界 16，并非数学意义上的无限大。

| 时刻 | R1 对 N1 的认知 | R2 对 N1 的认知 | 产生问题的条件 |
| --- | --- | --- | --- |
| 正常 | 直连，1 | 经 R1，2 | 两台设备的认知一致 |
| 故障刚发生 | 直连失效，16 | 仍经 R1，2 | R2 尚未获知故障 |
| 旧通告传到 R1 | 误认为经 R2，3 | 旧记录仍在 | R1 无法从距离值看出 R2 依赖自己 |
| 后续轮次 | 度量继续增长 | 度量继续增长 | 直到双方把 16 视作不可达 |

补充说明：若每次只能在约 30 秒的周期更新时推进一个度量，跨多轮传播就可能持续数分钟。教师用“约 16 轮、约 8 分钟”说明等待可能很长（13:39–14:09）。这只是用于感受时间量级的课堂估算；具体故障时长受触发更新、定时器、拓扑、分割规则和消息到达顺序影响，不能把它写成任何 RIP 网络固定的收敛时间。

教师提到水平分割、触发更新、毒性逆转等改进（12:13–13:38）。水平分割针对“从某邻居学来的路径又原样告诉该邻居”这一典型误导；毒性逆转可向该邻居声明这条路径不可达；触发更新在状态改变时及时发送消息。它们能减少部分误导情况，但更复杂的拓扑与更新顺序仍需结合路由失效阈值及计时器处理。理解这些方法时要指出各自改变了什么消息，而不能把任何一项理解成全网同时知道故障。

课堂最后归纳 RIP 的适用限制：最大可用跳数为 15，定期交换较完整的路由信息会产生通信量，故障时旧信息又可能影响收敛（14:12–15:03）。在小型、结构简单的网络里，其规则容易理解和管理；网络规模及恢复时间要求增加时，就需要考察其他路由协议的能力。学生在随堂答题中有同学把“向邻居发送”与“向全 AS 洪泛”混淆，教师在 16:54–17:42 专门纠正：RIP 更新交给相邻邻居，邻居还需经过后续交换才可能使更远的设备获知。

## OSPF 链路状态与路径计算（17:42–23:26）

OSPF 是自治系统内部使用的链路状态路由协议。教师提出 RIP 的核心限制：收到的是其他路由器对目的网络的距离与可达性说明，接收者不知道这条可达性依赖哪些完整连接（17:42–18:28）。OSPF 传播链路状态，让本区域的设备掌握“谁与谁相邻、连接代价是什么”，随后各自依据相同的信息计算路径（19:45–23:09）。

课堂使用“洪泛”描述链路状态信息向相关范围内传播。源路由器将自己的相邻关系和链路代价组成链路状态信息，邻居继续传递，使区域内的路由器都能获得；这个过程与 RIP 只向直接邻居通告距离向量的范围不同（19:58–21:04）。链路状态分组的内容围绕本路由器的局部连接，不需要把“我能到达的所有网络及当前距离”逐条充当原始拓扑。其他设备把各路由器的信息合在一起，形成一致的链路状态数据库。

补充说明：把数据库抽象成有权图 $G=(V,E,w)$。$V$ 是路由器及必要的网络节点，$E$ 是已知连接，$w(e)$ 是连接的代价。某路由器以自己为起点，计算到目标的最小总代价；当代价可累加且不存在负权时，可使用 Dijkstra 算法。例如 R1 到 R4 有两条路径：`R1-R2-R4` 的代价为 $2+7=9$，`R1-R3-R4` 的代价为 $4+3=7$，按该代价定义应选择后者。若系统改变代价赋值，路径选择也可能改变，因此“最短”要说明采用的度量。

链路双向的代价也可以不同。假设 R1 到 R2 代价 2，R2 到 R1 代价 5，那么 R1 作为起点的最短路径结果不能直接反向当作 R2 的结果（22:46–23:09）。每个路由器根据相同的拓扑信息，以自身为起点计算自己的下一跳。发生链路变化时，相关状态重新传播并触发计算；“所有人知道拓扑”表示信息可以传播到区域内，并不表示每个瞬间的数据库已经同步完成。

**【理解重点】OSPF 交换的是链路状态，路径由各路由器自行计算。**一份到达目标 N 的路由可以根据拓扑重新计算，不必仅依靠邻居口述的旧距离。这解释了教师在 17:54–18:20 的“知道怎么到”的课堂说法。OSPF 的名称中“开放”指协议公开，“最短路径优先”说明路径计算方法；教师还提到 IS-IS 同样使用最短路径计算，名称本身不能作为两者独有算法的依据（18:28–19:43）。

## OSPF 区域、骨干与路由器角色（23:23–27:40）

当 AS 很大时，让链路状态持续覆盖整个 AS 会增加数据库与传播负担。教师介绍把 AS 分为多个 `area`，在区域内部传播详细链路状态，再由区域边界路由器传递必要的区域间可达信息（23:23–25:28）。区域边界提供两项作用：连接不同区域，以及把区域内可达信息转化为区域间可以使用的信息。普通区域内部路由器主要维护本区域的详细拓扑，无须持有其他区域每一条内部连接（25:37–25:55）。

OSPF 的骨干区域标识为 `0.0.0.0`，也可按数值写为 `area 0`。教师说明其余区域通过区域边界路由器与骨干区域发生联系（24:35–25:20）。这里需要记住的是区域标识、区域边界角色与信息传播范围，不要把“骨干”理解成物理上必须放在网络中心的一台设备。骨干区域可以由多台路由器及其链路构成；区域边界路由器可以同时参与骨干与其他区域。

课堂以骨干路由器、区域边界路由器和区域内部路由器区分角色（25:55–26:21）。骨干路由器位于骨干区域；区域边界路由器在不同区域之间承担连接；内部路由器在所属区域内工作。角色由路由器参与的区域和具体作用决定，不由名字中的数字或物理机房位置决定。若某设备被标注为 R3，题目仍须给出它参加哪些区域，才能据此判断角色。

教师口述单个区域的规模建议，并将其与 RIP 的 15 跳界限对照（24:11–24:33）。两项数字衡量的对象不同：一个是区域包含设备的规模建议，另一个是 RIP 可用路径的最大度量。一个区域里有许多设备也可能每条路径都较短；一条直线形连接即使设备较少也可能使跳数很大。比较协议支持规模时，应分别写明度量、拓扑结构、数据库大小与更新负担。

## OSPF 更新次序与分组功能（27:40–35:14）

教师提到 OSPF 可以使用较灵活的链路代价，支持可变长度的子网和无分类前缀，也讲到消息鉴别与序号（27:40–29:55）。序号用于区分同一来源状态信息的新旧：链路先故障再恢复，两份消息经不同路径传播时，恢复消息可能先到，故障消息后到。接收者依据版本先后接受较新的状态，避免旧消息覆盖新状态。把序号当作“事件发生顺序的依据”即可理解课堂例子；它并不要求各设备的物理时钟完全一致。

OSPF 报文首部包含版本、类型、长度、路由器 ID、区域 ID、校验与鉴别相关信息。**【教师强调】首部格式需要能够识读，不要求默写整个字段顺序。**（29:58–31:18）路由器 ID 是识别路由器的标识。教师用所配置接口地址的最大值说明一个常见选取情形（30:26–30:52）；实际设备还可能受显式配置及其他接口选择规则影响，解题应按题干给出的 ID 或配置判断。区域 ID 说明消息归属的区域，不能用路由器 ID 替代。

课堂列出的五类 OSPF 分组是 Hello、Database Description、Link State Request、Link State Update、Link State Acknowledgment（31:19–32:42）。Hello 用于发现并保持邻居关系；数据库描述让邻居知道彼此有哪些状态信息；请求用于索取缺少或更新的内容；更新承载实际状态信息；确认用于可靠传播的反馈。教师用新路由器加入后的信息同步串起后面三种类型。阅读报文时，先判断它承担“发现、描述、索取、发送、确认”中的哪项任务，再解释它在同步流程中的位置。

补充场景：R1 已经掌握区域数据库，R2 刚加入。两者先通过 Hello 识别邻居，交换数据库概要；R2 根据概要发现某条状态缺失，向 R1 请求；R1 发出更新，R2 收到后确认。待数据库满足同步条件，R2 才能利用完整且较新的拓扑信息计算路径。若 R2 只拿到概要而没有拿到所需状态，就不能说它已经知道全区域的拓扑。

教师借时序图描述状态更新的传播与确认，并口述周期刷新、状态保持的不同时间量级（32:42–34:28）。课堂重点是：拓扑变化时尽快传播，状态未变时避免反复发送全部详细信息，定期维护状态仍然必要。对于报文具体计时器，设备配置和 OSPF 版本会影响数值；课堂口述的“30 秒”和“30 分钟”应放回各自语境理解，不要统一写成所有 OSPF 消息固定的发送间隔。响应时间的口述值也不能单独当作任意网络的性能保证。

在多路由器共享同一接入网络时，教师介绍指定路由器 `DR` 的概念：通过代表设备协调该网络上的链路状态交换，减少每对路由器重复交换信息的负担（34:30–35:14）。这一安排发生在特定多点接入环境。若题目只给出两个路由器间的点对点连接，不能凭“运行 OSPF”便假设存在同样的 DR 选举情形。

## BGP 的目标、属性和相邻关系（35:14–44:08）

教师在 36:07–36:55 强调网络层是课程重点，随后于 37:34 进入外部网关协议 BGP。RIP 与 OSPF 用于 AS 内部；跨 AS 时，不同管理者可以采用不同代价与商业政策，很难让所有 AS 以同一条链路代价标准计算全网最短路径（37:34–39:10）。BGP 的首要任务是交换前缀可达性与 AS 路径，让本 AS 依据政策选择可接受的路径。教师举出机构之间的政策、商业关系、成本及负载等考虑（39:11–40:40）。

补充说明：到前缀 P 有路径 `AS1-AS2-AS5` 和 `AS1-AS3-AS4-AS5`，跳过的 AS 数量不同，但 AS1 是否采用较短的第一条路径，还可能取决于允许经过哪些邻居、业务成本和本地政策。不能只按 AS 个数宣称某条一定会被选中。BGP 路径中记录经过的 AS 序列，有助于检查自身 AS 是否再次出现在路径里；若出现，可识别潜在的 AS 级环路。序列能显示域间方向，但无法还原每个 AS 内部每一台路由器的完整连接。

教师介绍 BGP 路径属性采用带类型与长度的信息形式，以便设备识别已知属性，并按规则处理不认识的属性（40:40–42:43）。`Type` 告诉接收方属性种类，`Length` 告诉属性占用多少内容，`Value` 承载具体值。已知属性中有必须随更新携带的类别，也有可以按情况出现的类别；可选属性又涉及不识别时是否继续向外传递。课堂旨在说明 BGP 能携带丰富政策信息，讲义不凭这段口述推断某一具体属性在某台设备上的最终选择顺序。

BGP 发言人由 AS 管理者选定，通常位于 AS 边界；两个发言人建立 TCP 连接，并在其上建立 BGP 会话来交换路由信息（42:43–44:08）。TCP 提供可靠的字节传输，为协议交换提供基础；BGP 自身仍需负责邻居状态、路径属性和更新处理。一个 AS 与多个邻接 AS 交换信息时，可以有多个发言人。发言人间的“相邻”是 BGP 会话关系，需要区分物理邻接、IP 可达与协议会话三个层次；课堂使用共享网络连接作示例。

## BGP 路径向量、消息类型与拓扑边界（44:08–51:09）

BGP 更新围绕“哪些目的前缀可经哪些 AS 到达”。教师用主干 ISP、地区 ISP、本地 ISP 及若干目标网络说明：发言人能够告诉相邻 AS，经 AS2 可以到达一组网络；更完整的路径还可表达需要经过的其他 AS（44:08–46:56）。AS 内部具体采用 RIP、OSPF 或其他机制，属于该 AS 的管理范围；外部发言人关注本域应把分组交给哪个方向，以及宣告路径是否符合本地政策。

对于一个目的前缀，路由信息可概括为目标前缀、下一跳、AS 路径及其他路径属性。下一跳是接收 AS 用来寻找域间出口的重要线索；AS 路径说明经过的自治系统序列。课堂在 47:41–48:17 提到 BGP 支持无分类前缀，并强调下一跳和 AS 序列同时存在。答题中若只写“下一跳”而没有 AS 路径，就无法解释域间环路检测；若只写“AS 路径”而不考虑本地如何到达出口，也不能完成实际转发。

教师说明 BGP 主要消息类型为 OPEN、UPDATE、KEEPALIVE、NOTIFICATION（49:01–49:17）。OPEN 用于会话建立时交换必要参数，UPDATE 通告或撤销路由，KEEPALIVE 保持会话，NOTIFICATION 报告导致会话异常的错误。消息名称适合按协议会话的生命周期记忆：先建立，再交换与维护，异常时告知。教师说 BGP 细节丰富，本节只作基本介绍（49:19–49:37）。

课堂末尾再次确认，OSPF 的区域数据库能够提供所属区域的详细链路信息；BGP 给出的主要是 AS 路径序列，不能据此拼出全球每台路由器的完整拓扑（50:30–51:01）。这也帮助理解三个协议的“已知信息”层次：RIP 依赖邻居报告的目的距离；OSPF 依据传播的链路状态计算区域内路径；BGP 使用域间路径与政策选择。教师的课堂答题在 50:17–50:28 有“未提交”的提醒，转写未说明该答题单独计分，不能据此推断分值。
