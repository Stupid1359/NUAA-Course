## NAT 往返地址转换与地址池（01:40–05:05）

教师继续上一节的示例：内部主机 A 的地址为 `192.168.0.3`，NAT 出口使用外部地址 `172.38.1.5`。A 发往外部主机 B 的报文到达 NAT 设备，出站时源地址改为 `172.38.1.5`；B 的回复以这个外部地址为目的；NAT 设备收到回复后，把目的地址改回 `192.168.0.3`，再送进内部网络（01:40–02:47）。这两个改写位置分别在去程和回程，改写的字段也不同。

| 阶段 | 源 IP | 目的 IP | NAT 的动作 |
| --- | --- | --- | --- |
| A 发出 | `192.168.0.3` | B 的地址 | 准备出站转换 |
| 边界设备送出 | `172.38.1.5` | B 的地址 | 改写源 IP，保存对应关系 |
| B 回复 | B 的地址 | `172.38.1.5` | 到达边界设备 |
| 边界设备转入内部 | B 的地址 | `192.168.0.3` | 查记录并改写目的 IP |

NAT 转换表维护内部地址和外部地址的对应关系，保证返回数据能够找到内部接收者（02:08–02:39）。只看外部地址本身，并不能判断发起通信的是哪台内部主机；设备需要已有映射或管理员设置的静态规则。还要注意，转换设备若改动 IP 首部相关字段，就必须保证校验与协议状态一致。课堂没有展开这些实现字段，解题时主要写清两次转换与对应表。

教师接着介绍外部地址池：NAT 设备可持有多个全球地址，按需分配给内部通信使用（02:47–03:21）。在课堂讨论的纯地址一对一动态转换模型中，若池中有 $n$ 个地址，同一时刻最多为 $n$ 个占用地址映射的内部主机提供该种转换；地址释放后可以轮流使用。这里的“最多 $n$ 台”以一个外部地址同一时刻只给一个内部映射为条件，随后讲到的端口转换会改变这个并发限制。

教师说这种动态地址转换下，内部服务若要长期供外部用户访问，需要稳定的外部访问方式（03:31–04:42）。补充说明：内部主机并非天然无法运行服务器，实际能否被外部主动访问取决于是否有稳定的地址映射、端口映射、防火墙规则和名称解析。课堂给出的校园案例是向管理部门申请固定外部地址。理解教师的提醒时，重点是动态出站映射不能自动提供可靠的外部入站入口。

## NAPT：同时转换 IP 地址与端口（05:05–10:17）

纯地址一对一映射需要足够多的全球地址。教师于是引入 NAPT：在地址转换之外，利用 TCP 或 UDP 的端口号区别内部通信，使多个内部主机或进程共用一个外部 IP 地址（05:05–05:32）。边界设备用“外部地址、外部端口”对应“内部地址、内部端口”，回程报文到达后据此恢复目标。课堂指出，同一公网 IP 上出现不同端口，即可对应不同内部通信（05:38–07:03）。

补充双连接例子：内部 `10.0.0.2:51000` 与 `10.0.0.3:52000` 均访问外部服务。NAPT 可把前者映射为 `198.51.100.8:3500`，后者映射为 `198.51.100.8:3501`。两份外部报文的源 IP 相同，源端口不同；回复分别发往 `198.51.100.8:3500` 与 `198.51.100.8:3501`，转换表据端口送回对应内部地址。`198.51.100.8` 在此只作为说明性示例地址，不是课堂投影中的原数值。

| 内部源 | 外部源 | 回复进入边界时的目的 | 内部最终目的 |
| --- | --- | --- | --- |
| `10.0.0.2:51000` | `198.51.100.8:3500` | `198.51.100.8:3500` | `10.0.0.2:51000` |
| `10.0.0.3:52000` | `198.51.100.8:3501` | `198.51.100.8:3501` | `10.0.0.3:52000` |

教师特别把服务对象从“不同用户”进一步说到“不同用户进程”：一台主机可能同时运行多个使用网络的进程，各进程分别持有端口和连接状态（07:04–08:08）。因此一个内部主机也可能占用多条映射记录。计算可服务主机数时，不能把“可用端口数”直接当作“可用主机数”；一台主机的并发连接、保留端口、协议类别和转换设备资源都会影响实际数量。

TCP 与 UDP 的端口字段各为 16 bit，理论编码空间为 $2^{16}=65536$ 个值，即 0 到 65535（08:27–09:19）。教师用这一数量级说明单个公网地址配合端口后，能够容纳远多于一对一地址转换的并发通信。补充限制：并非全部端口都可任意分配，端口冲突、保留范围、设备转换表容量、超时设置及目标连接条件均会限制真实并发数。课堂口述的“六万多”适合说明数量级，不能承诺某台设备固定支持 65536 条有效连接。

回程转换还要把外部目的端口恢复成内部端口（09:34–09:56）。如果只恢复目的 IP，多个内部进程仍可能无法区分；如果只恢复端口，内部网络也无法找到具体主机。写 NAPT 往返过程，至少给出内部二元组、外部二元组及协议类别；若题目给出完整连接信息，还应结合目的端信息查找会话。**【理解重点】NAPT 扩展并发的依据是同一外部地址可搭配不同端口表示不同映射。**

## NAT 的能力边界与端到端通信（10:17–12:28）

教师说明 NAPT 缓解 IPv4 地址不足，同时带来协议处理和应用连接问题（10:17–12:18）。传统路由器按网络层地址转发，NAPT 需要检查并修改传输层端口，设备因此要维护会话映射。某些应用要求外部设备主动连接内部主机，若没有静态映射、穿越机制或其他允许规则，外部一方无法直接确定目标内部地址和端口。公网端点与内部端点之间的直接通信模式因转换而受到影响。

并非所有 IP 负载都有 TCP 或 UDP 端口。教师以直接承载在 IP 上的协议为例，提示“把端口加入地址转换”的办法不能原样套用在无端口报文上（11:24–11:58）。分析 NAT 对协议的影响时，先看 IP 首部的 `Protocol` 值及负载格式，再判断是否存在可用于区分连接的端口。把 NAPT 的 TCP/UDP 表项结构强行用于无端口协议，会得出没有依据的映射结论。

教师认为 IPv6 才是从地址空间上处理 IPv4 资源不足的长期路径，而 NAT 为 IPv4 继续运行提供了重要条件（11:58–12:18）。这段评价与第 27 节 IPv4/IPv6 共存内容呼应。要分清“地址可以重用”和“通信已经具备端到端可达性”：NAPT 让内部出站通信可复用少量外部地址，并不自动赋予外部主动访问内部所有服务的能力。

## MPLS：标签转发的目标和工作范围（12:28–20:00）

教师随后进入多协议标签交换 MPLS。课堂从传统 IP 分组逐跳查找转发表的过程出发，说明 MPLS 在进入其工作范围时为分组加入标签，后续标签交换路由器依据标签与本地转发表处理（12:28–14:54）。MPLS 的“多协议”说明它能够与多种网络层和链路层技术配合；“标签交换”说明转发时使用标签作为关键匹配信息。设备仍需要路由信息或其他控制信息确定路径，标签并非凭空决定最终目的地。

在 MPLS 工作范围的入口，路由器根据分组特征进行分类并附加标签；中间路由器查入标签、选择输出接口并改写标签；出口去掉相关标签，继续按普通 IP 或后续封装方式处理（18:35–20:00）。发送和接收的端系统通常无须直接理解工作范围内的标签，这就是教师说的“对端系统透明”（15:45–17:07）。工作范围外部仍可按通常的 IP 转发与应用协议通信。

课堂提到 MPLS 可用于流量工程、负载安排和 VPN 等应用（17:07–17:46）。标签路径可以由网络管理者依据业务和链路目标安排，使来自不同入口或不同业务的分组采用不同转发策略。它能够为服务质量管理提供工具，但是否真正获得某种时延或吞吐保证，仍需具体资源预留、路径配置和设备策略。不能只凭分组带有 MPLS 标签就推断该流已经获得确定性能保证。

教师把标签转发称为介于链路与网络处理之间的方式，并用“2.5 层”帮助定位（18:35–19:16）。这个说法是教学上的层次比喻，协议的具体封装取决于承载方式。标签交换路由器 `LSR` 同时具有参与路由选择或标签分配的控制能力，以及按标签查表的转发能力（19:16–19:56）。课堂将标签匹配与硬件快速处理联系起来；实际性能由芯片、表结构和设备实现决定，不能简单认定所有 IP 查表均由普通软件逐包慢速执行。

补充流程：对于目的前缀 P，控制机制使入口及中间节点建立到出口的标签转发关系。来自主机的 IP 数据报进入入口，入口识别 P 所属的转发类别并加入供下一节点识别的标签。中间节点收到后只需依据本地表确定下一跳及输出标签。出口移除标签并继续处理目的 P。若中途链路变化，控制机制还需更新相应表项；原有标签并不能自行绕开故障。

## 标签路径、LDP 与入口分类（20:00–26:58）

教师用入口、若干中间节点和出口说明标签交换路径 `LSP`。标签分配协议 `LDP` 可协助相邻节点通告标签绑定；数据进入 MPLS 工作范围后，按已建立的标签路径前进（20:00–21:46）。这里要区分两个同名缩写：前一节 OSPF 中的链路状态分组也常写作 `LSP`，本节 MPLS 的 `LSP` 指 Label Switched Path，即标签交换路径。阅读讲义时看所在协议与上下文。

进入入口时，设备对分组分类，确定其所属转发等价类 `FEC`（21:47–22:03、24:54–26:08）。FEC 是一组需要按相同转发方式处理的分组；课堂举出的共同属性包括下一跳、服务优先级及丢弃处理（25:07–25:39）。若两个分组的目的前缀相同，但管理员希望一个走高容量路径、另一个走低时延路径，就可以根据业务条件把它们分入不同 FEC；若处理方式完全相同，则可以共享相应类别和标签绑定。

补充说明：分类依据可以涉及目的前缀、入口、服务类别或其他策略，具体取决于网络配置。课堂说一个 FEC 的分组在某入口可赋予相同标签（25:42–26:08），表示它们在该位置采用相同转发处理。不能把这个局部映射推广成全网所有路由器都必须使用同一个标签数字。下一节会看到每个路由器可独立选择本地标签数值。

教师用两位来源主机 H1、H2 的流量举例：若单纯依据某个目的地址选择路径，两路流量可能集中到同一方向；把它们区分为不同 FEC 后，可安排经不同 MPLS 路径转发，从而分担链路负载（26:19–26:56）。判断这种分配是否合理，还要看路径容量与拥塞状况。FEC 只是提供可管理的分类单位，实际负载均衡仍由控制策略确定。

## MPLS 标签字段及以太网类型识别（26:58–30:22）

教师介绍常见 MPLS 标签项为 4 B，包含 20 bit 标签值、用于服务类别处理的位、标志当前标签是否处于最内层的 `S` 位，以及限制转发次数的 `TTL`（26:58–28:34）。多个标签项可以连续封装，最外层供当前转发范围使用；去除外层后，内部标签可能继续参与另一层转发。`S` 位帮助识别最内层位置，`TTL` 每过相应转发节点调整，限制持续循环的风险。

20 bit 标签字段提供 $2^{20}=1,048,576$ 个编码值，但这不等于一台设备能同时维护这么多条有效业务流（28:01–28:17）。实际可用数值、保留值、设备转发表容量及同一标签的本地意义都需要考虑。课堂把数量级用于说明标签空间大；写计算题时可给出 $2^{20}$，同时说明“编码值数量”与“可承载进程数”不是同一指标。

以太网帧接收端需要先判断上层负载类型。教师回顾帧的 `Type` 字段，指出普通 IPv4 的 EtherType 为 `0x0800`，MPLS 单播为 `0x8847`，多播为 `0x8848`（28:36–30:19）。这些值可帮助设备把帧交给相应处理模块。若类型指向 MPLS，接收设备按标签项理解负载；若类型指向 IPv4，直接按 IP 首部处理。课堂还提到 PPP 中有对应的协议标识，具体数值听写可能不够清楚，讲义不据此设置额外背诵要求。

补充封装判断：一帧从路由器 A 到路由器 B，帧首部中的源、目的 MAC 负责这一跳传送；EtherType 指向 MPLS；标签项中的当前标签供 B 查表；标签之后承载原有 IP 数据报。即使原 IP 目的地位于更远网络，B 处理该帧时也先依据本地标签决定下一步。下一跳发送的新以太网帧还会有新的链路层源与目的地址。

## 下游标签分配与逐跳交换（30:22–38:22）

课堂指出，要理解数据转发，需要把标签分配过程补齐。先由路由信息确定目的网络的方向，再由路径下游节点为某个 FEC 分配本地可识别的标签，向上游通告“请给发往我的这类分组使用这个标签”（30:30–33:43）。例如路径为 R1→R3→R5，R5 给 R3 通告一个供 R5 识别的标签，R3 再给 R1 通告供 R3 识别的标签。标签数字可不同，分配方向沿下游到上游，数据实际发送方向沿上游到下游。

这种方向安排来自标签的使用者：下一台路由器负责读取收到的标签，所以由下一台设备决定自己想读取哪个值（31:19–33:14）。R3 发往 R5 时，附加 R5 分配的标签；R1 发往 R3 时，附加 R3 分配的标签。若 R1 自行选一个 R3 从未分配的数值，R3 的入标签表无法据此确定动作。**【理解重点】标签由接收该标签的下游设备分配，发送设备按通告加上标签。**

教师随后用 A、B、C、D 路径解释每跳操作（33:43–36:25）。A 作为入口按分组类别加入 B 分配的标签；B 根据入标签查表，确定输出接口及 C 分配的标签，用新标签替换旧标签；C 做相同的查表与替换；到出口时，标签被去除，继续处理普通 IP 分组。入标签是当前设备用来匹配的值，出标签是下一设备要识别的值。把“入”和“出”写成永远相等，会失去逐跳交换的含义。

补充数值例子：B 向 A 宣告，对 FEC F 使用入标签 100；C 向 B 宣告，对同一 FEC 使用入标签 200。A 发给 B 的分组携带 100。B 查得 `入标签 100 → 输出接口至 C，出标签 200`，改写标签并发送。C 用 200 识别 F。若 C 也选择 100，仍可能成立，只要 B 的输出标签与 C 所分配的入标签一致。不同设备的标签数值没有必须递增、相等或互异的全球规则（36:26–38:22）。

| 所在位置 | 当前节点识别的标签 | 下一跳所需标签 | 处理结果 |
| --- | --- | --- | --- |
| A 入口 | 先识别 FEC F | B 要求 100 | 加入 100 后发送给 B |
| B 中间节点 | 100 | C 要求 200 | 查询表项，把 100 改为 200 |
| C 后续节点 | 200 | 由后续节点确定 | 按本地表继续处理 |

一个节点可以为不同 FEC 维护不同表项。若同一设备、同一匹配上下文中两条完全相同的入标签对应不同动作，收到分组时就无法唯一决定处理方式；教师在 41:17–42:57 的即时答题中强调这一点。不同接口或不同标签空间的实现细节由具体设备决定，课堂题目应按给出的表项环境判断。

## 出口去标签与倒数第二跳处理（38:22–41:04）

分组离开 MPLS 工作范围时，需要去除用于该范围的标签，让出口或后续设备继续处理内部 IP 数据报（38:22–38:48）。教师提出是否可以在出口前一跳就移除标签：若前一跳已确定下一跳就是出口，且出口接下来只需按内部 IP 继续转发，前一跳可以先执行去标签动作，出口收到普通 IP 数据报（38:48–40:40）。这个做法通常称倒数第二跳弹出标签。

补充路径例子：A→B→C→D，D 是出口。如果 C 的转发表已确定把该 FEC 送给 D，且 D 无须利用最外层标签选择进一步的 MPLS 动作，C 可在发送前移除这层标签。D 按 IP 数据报继续处理，少一次外层标签查找与移除。教师还指出出口可能汇集多个前一跳，提前去标签可以减少出口工作量（40:16–40:40）。是否适用仍由已建立的标签路径及业务封装决定。

多层标签时，移去最外层后，内部标签仍可能需要保留并参与下一阶段的转发；课堂以 VPN 相关场景提示这一点，未展开具体服务类型（40:40–41:03）。因此“弹出一层标签”与“所有标签全部消失”属于不同动作。分析题目若画了两层标签，应逐层写出标签状态，避免在前一跳把内部业务标签也一并去除。

教师的课堂选择题还要求理解入标签与出标签之间没有固定数值关系：它们分别由当前设备和下游设备使用，可能相同，也可能不同（43:05–44:05）。如果题目只给入标签 100，却未给下游分配结果，就不能推算出标签一定为 101 或 100。需要查标签分配与本地转发表。

## SDN 的控制平面、数据平面与流表（46:37–51:11）

教师最后介绍软件定义网络 SDN：网络设备的转发行为由控制层面的程序与规则管理，数据平面设备执行实际转发（46:37–47:52）。控制器掌握其管理范围内的拓扑与策略，计算相应路径；交换机按照收到的流表项匹配和处理数据。课堂把控制层面的应用接口称为北向接口，把控制器对交换机的控制接口称为南向接口（47:55–48:39）。接口名称说明交互方向，实际协议与控制器实现需要按部署环境确认。

教师举出的起始情形是某交换机尚无匹配流表项：交换机将必要的分组或元信息交给控制器；控制器依据拓扑与策略确定路径，并向相关交换机下发流表；随后同类分组在交换机上直接匹配已安装的规则并转发（48:42–50:24）。控制器处理的是规则与路径安排，交换机执行的是具体分组处理。对每一个分组是否都需要询问控制器，取决于是否存在匹配规则、超时及策略；课堂例子描述的是“首次无匹配项”时的处理。

流表项至少需要表达匹配条件和动作：例如匹配“从端口 1 进入、目的前缀为 P 的分组”，动作为“从端口 3 输出”，还可能包含修改字段、计数、优先级等配置。控制器若要让路径经过四台设备，需要使相关设备都获得相应规则，否则分组走到下一台时仍可能没有匹配项。课堂用四台交换机说明控制器沿路径下发规则的过程（49:39–50:16）。

**【理解重点】SDN 的可编程性体现在控制器能够调整转发策略并更新设备规则。**教师在 50:24–51:11 强调控制与转发由不同部分承担。需要注意控制器管理范围、规则安装时机和故障处理都依赖实现；“控制集中”不等于任何时刻全网只有一台设备，也不意味着每个交换机本身没有处理能力。课程本节只介绍基本结构，后续会继续讲具体内容。
