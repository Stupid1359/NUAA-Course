## IPv4 与 IPv6 长期共存的两种方式（01:14–08:52）

### 双协议支持的职责

教师回顾 IPv6 推广需要长期与 IPv4 并存，因此终端或路由器可以同时具备两种协议能力（01:14–03:09）。在这种配置中，设备与 IPv4 对端通信时使用 IPv4 地址和报文格式，与 IPv6 对端通信时使用 IPv6 地址和格式。两套网络功能可以并存，具体应用选择哪种地址由 DNS 结果、操作系统策略和网络可达性决定。设备同时支持两种协议，并不自动意味着一个只会 IPv4 的终端能够直接解析 IPv6 数据报。

课堂把双协议设备跨 IPv4 与 IPv6 网络的通信描述为“翻译”。若实际部署需要两个协议版本之间转换，还须有明确的地址和报文转换机制；单有双协议能力只能说明设备分别处理两种协议，不保证跨版本通信无条件成立。IPv6 地址是 128 bit、IPv4 地址是 32 bit，地址映射和应用可达性需要按具体方案处理，不能只把 32 bit 直接拼接进某个 128 bit 字段就当作所有场景的通用转换（03:09–04:33）。

教师指出若把 IPv6 报文改造成 IPv4 报文，又想在另一端恢复，IPv6 首部的 Flow Label 等字段可能没有对应位置可保存（04:36–06:09）。这是跨版本逐字段转换需要考虑的信息损失。若业务依赖相关扩展首部、流标签或特殊地址类型，转换规则还需要定义如何处理缺失字段。解题应把“设备支持两个协议版本”和“在两个版本之间转换报文”分别陈述，避免由前者推断后者必然发生。

### 隧道中的外层与内层地址

隧道方法在进入 IPv4 网络时，把完整 IPv6 数据报作为外层 IPv4 数据报的负载；到隧道出口时，去除外层 IPv4 首部，继续按内层 IPv6 数据报转发（06:09–08:52）。内层源、目的 IPv6 地址代表真正的 IPv6 通信双方，外层源、目的 IPv4 地址代表隧道入口与出口。课堂图中用 A、F 表示通信两端，B、E 表示隧道两端（07:56–08:25）。

| 位置 | 外层 IPv4 首部 | 内层 IPv6 数据报 | 转发依据 |
| --- | --- | --- | --- |
| 隧道入口之前 | 尚未加入 | 原始 IPv6 数据报 | 目的 IPv6 地址 |
| 穿越 IPv4 网络 | 源为入口、目的为出口 | 作为 IPv4 负载保留 | 外层目的 IPv4 地址 |
| 隧道出口之后 | 已移去 | 继续按原始内容处理 | 内层目的 IPv6 地址 |

补充长度分析：若内层 IPv6 数据报长 1200 B，外层 IPv4 首部按 20 B，封装后的 IPv4 数据报至少长 1220 B；实际隧道还可能有附加封装开销。若隧道路径 MTU 较小，入口必须考虑外层新增字节，否则原本能在 IPv6 链路通过的报文可能在 IPv4 段遇到 MTU 问题。隧道能保留内层字段，不代表中间 IPv4 路由器会识别或执行内层 IPv6 的服务要求；中间设备主要依据外层首部转发。

**【理解重点】隧道入口与出口是外层通信双方，原始主机是内层通信双方。**抓包中同一个封装报文可同时看到两套地址，提问“当前 IPv4 网络将报文送到哪里”应回答隧道出口，提问“最终 IPv6 目的地是谁”应回答内层目的地址。把两套地址混在一起，会误读路径和封装层次。

## ICMPv6 与邻居发现（08:52–17:19）

教师介绍 ICMPv6 作为 IPv6 的辅助控制协议，可报告差错、提供查询信息，并承载邻居发现及多播成员管理相关功能（08:52–10:38）。IPv4 环境中常见的 ARP、ICMP 和 IGMP 各有任务；IPv6 的相关功能通过 ICMPv6 消息及相应协议安排实现。IPv6 主机寻找同链路邻居的链路层地址时使用邻居发现机制，不发送 IPv4 的 ARP 请求。ICMPv6 还服务于路由器发现、地址配置与重复地址检测等工作。

IPv6 同样使用尽最大努力交付，因此链路故障、路由问题和过大报文仍需要诊断信息。若路由器因下一链路 MTU 太小无法转发 IPv6 报文，可以返回 ICMPv6 Packet Too Big，让发送端调整大小；这与上一节“IPv6 中间路由器不进行分片”相互衔接。ICMPv6 报文仍受网络策略和安全规则影响，某个错误未得到回复不能直接证明错误不存在。

课上进行了 IPv6 基础答题（10:38–17:19），问题涉及地址长度、广播与任播、链路本地地址的用途。IPv4 地址为 32 bit，IPv6 地址为 128 bit；IPv6 不使用传统广播地址；任播让一组共享任播地址的接口中某个成员接收；链路本地地址可用于所在链路的邻居发现与自动配置。教师在 14:50–14:58 明确纠正了“本地站点”和“链路本地”的混淆。投影选项与完整题目没有全部写入转写，讲义保留能够核实的知识结论。

补充诊断例子：终端配置了 IPv6 全球单播地址，却不能到达默认网关。应先检查接口链路状态、链路本地地址、邻居发现结果和路由器通告；若本地邻居都无法解析，直接研究远端 BGP 路由意义不大。反过来，邻居发现成功也只说明本地下一跳可达，远端地址仍可能因路由策略或目的服务状态而无法通信。

## 路由选择的目标与分类（17:19–20:44）

教师在 17:19 开始讲路由选择协议，指出本章 IP 协议和路由选择协议是两块主要内容。路由算法需要正确、完整，尽量简单，并对通信量和网络拓扑变化作出响应；稳定性、公平性与“最佳性”也要结合具体目标讨论（17:39–18:49）。一个路径对最少跳数最优，可能在时延、容量或管理政策方面并不最优，所以“最佳”必须说明采用何种度量。

静态路由由管理员配置或按固定规则提供，适合简单拓扑、默认出口及特定策略；动态路由由设备交换路由信息，并在变化后重新计算（19:57–20:44）。静态配置的优点是可控且没有持续协议交换开销，但网络变化需要相应的管理或自动化处理。动态协议有控制报文和计算成本，却可以在规则允许的范围内对故障、连接变化及新网络作出响应。实际网络可同时使用静态和动态路由，二者承担不同目标。

补充例子：只有一个上级出口的小型网络可配置指向上级的默认静态路由；有多个可替换出口的大型网络通常需要动态协议及时反映可达性。即使使用动态协议，设备仍可能保留直连路由、默认路由和部分管理员指定路由。判断某条路由从哪里来，应查看路由来源，而不能凭“它是默认路由”推断它一定手工配置。

## 自治系统及内部、外部路由（20:44–29:34）

### 为什么把全网分成管理范围

教师说明互联网规模很大，让全球所有路由器都交换每个内部网络的详细拓扑信息，会耗费大量带宽与存储；不同机构也有各自的路由管理政策（20:44–22:21）。自治系统 AS 可以把统一管理的路由范围组织起来，在内部采用自己的协议和度量，对外宣布可达前缀及相应政策。外部网络通常需要知道某个前缀能由哪个 AS 方向到达，无须知道该 AS 内部每台设备的完整连接图。

一个 AS 可包含多个网络前缀与路由器，边界设备与其他 AS 交换域间可达信息（22:21–25:30）。课堂口述某时点登记 AS 与活跃 AS 数量级，但没有可在本节转写中核对的统计来源和统计日期，讲义不将该数值写成当前数量。判断是否属于同一个 AS，应看管理和路由政策边界，不能只凭地理位置或网络数量判断。

内部网关协议 IGP 在一个 AS 内传播路由信息，课堂后续讲 RIP 与 OSPF；外部网关协议 EGP 的协议大类在 AS 之间交换可达信息，当前实际广泛使用 BGP（25:30–27:48）。两个 AS 可以分别使用不同 IGP，边界设备仍可通过 BGP 等机制协同实现跨域到达。路由信息的交换与实际数据分组的转发是不同过程：控制协议决定或影响路由表，用户数据按已形成的转发表继续逐跳发送。

| 范围 | 常见协议示例 | 交换的主要信息 | 管理目标 |
| --- | --- | --- | --- |
| AS 内部 | RIP、OSPF | 内部前缀与可达路径 | 在同一管理范围选择内部路径 |
| AS 之间 | BGP | 可达前缀及路径政策信息 | 在不同管理范围之间确定方向 |

课堂解释历史文档中的 `gateway` 有时指现在所说的路由器，并提醒 `EGP` 既可能表示外部网关协议这一大类，也曾是某个旧协议的名称（28:14–29:28）。阅读旧资料时应按上下文识别。现代网络学习中，提到 BGP 应明确其为具体协议，提到 EGP 大类应明确其是域间路由协议的分类。

## RIP 的距离向量与基本约束（29:34–37:15）

### 跳数度量

教师以 RIP 介绍距离向量路由选择（29:34–30:11）。每台路由器维护到目标网络的距离和下一跳，RIP 用跳数作为距离度量：直接连接网络在课堂模型中距离为 1，经一个相邻路由器再去到达某目标，距离在邻居报告值基础上加 1（30:11–31:20）。RIP 选择跳数较少的路径，不按实际链路带宽、延时或光纤类型比较质量。等跳数路线的处理还与具体版本及设备实现有关，课堂例题中的规则是等距离时保留原路径，以避免频繁变化（48:51–49:17）。

RIP 把度量 16 视为不可达，可用路径最大度量为 15，因此只适合跳数范围有限的网络（31:20–32:46）。这一上限也限制“逐步把坏消息的跳数加大”时数值持续增长。它不能解决所有收敛问题，只把错误路由在特定计数上限定为不可达。若实际最短路径已经超过允许跳数，RIP 无法把该路径作为可用路由，即使物理连线仍存在。

### 邻居交换与收敛

RIP 向直接相邻的路由器交换路由信息，邻居再向自己的邻居传播；每台设备先知道直接连接的网络，再通过多轮交换逐步学习更远的前缀（33:00–37:15）。课堂说默认约每 30 秒发送一次更新；故障或变化可能触发额外通知，实际时效取决于实现和网络状态。网络在稳定后，各路由器对可达前缀及下一跳形成一致且有效的认知，称为收敛。收敛不要求每台路由器持有完全相同的“下一跳”，因为它们处在不同位置。

补充传播过程：R1 直连网络 N，R2 与 R1 相邻，R3 与 R2 相邻。R1 向 R2 通告 N，R2 学得经 R1 到 N；下一轮 R2 向 R3 通告，R3 才知道经 R2 到 N。若 R1 与 N 的连接突然中断，R3 也不能在故障瞬间自动得知，坏消息要沿协议更新传播。不同路由器在短时间内可能保持不一致视图，这正是距离向量协议需要故障处理机制的原因。

教师用“好消息较快传播、坏消息可能滞后”引出 RIP 的潜在路由环路问题（31:35–32:29）。当某条目的路径已经失效，相邻设备若仍互相声称能通过对方到达目标，就可能形成逐步增大的错误跳数。RIP 的度量上限、计时器以及其他防环机制可以缓解这种情形，后续课程会继续讲具体处理。

## 收到邻居更新后的 RIP 路由表计算（37:15–44:52）

### 先把邻居的距离换成自身候选距离

设当前路由器 R 收到邻居 X 的更新。对 X 宣告的每个目的网络，把其跳数加 1，得到“R 经 X 到该网络”的候选距离；若采用该候选，下一跳写 X（37:50–39:41）。例如 X 说自己到 N 距离为 3，R 经 X 到 N 的候选距离为 4。这个“加 1”是 R 到 X 的一步，不可遗漏，也不能因为 X 的原表下一跳是另一台路由器就让 R 直接把那台设备写作自己的下一跳。

路由更新可分成几类（39:41–43:52）：本地表没有该目标，候选可达时新增；本地已有目标但走别的邻居，若经 X 更短则改用 X，否则通常保留；本地当前目标本来就走 X，则应根据 X 的新宣告更新距离，即使距离变差也要处理，因为原来的下一跳已经改变了其可达判断；若 X 的完整更新中不再包含一条原本只经 X 可达的目标，课堂要求清除或标为不可达；与 X 无关的路由保持。更新是否完整、条目超时与失效细节需按实际协议报文和计时器解释，不能把任一单独的部分通告都当作完整路由表。

| 本地原状态 | 邻居 X 的新信息 | 课堂计算动作 | 原因 |
| --- | --- | --- | --- |
| 没有目标 N | X 报告可达 N | 新增经 X 的记录 | 获得新的可达性 |
| N 原经 Y，距离 5 | 经 X 的候选为 3 | 改成经 X、距离 3 | 候选更短 |
| N 原经 Y，距离 3 | 经 X 的候选为 5 | 保留经 Y | 候选更长 |
| N 原经 X，距离 3 | X 新报告使候选为 6 | 更新经 X 的距离或按阈值失效 | 原下一跳的信息已改变 |
| N 原经 X | X 的完整更新不再报告 N | 按失效规则移除或标为不可达 | 原依据不再有效 |

RIP 还用计时器识别邻居失效。教师介绍若约三分钟收不到相邻路由器更新，就把经该邻居获知的路由标为不可达，度量写成 16（43:52–44:52）。30 秒周期与约三分钟失效时间是课堂用于理解的常见配置值，实际设备参数仍由版本和配置决定。路由被标为不可达后，后续还会涉及保留及清除等状态；不能把“写 16”理解成物理接口立即被断开。

## 两组课堂路由更新例题（45:01–49:51）

教师先以 R6 收到 R4 更新为例（45:01–47:32）。做题的第一步是将 R4 宣告的每条距离加 1，候选下一跳统一改为 R4；第二步与 R6 原表按目的网络比较。课堂口述列出三种变化：原表缺少的目标新增；原来就经 R4 的路由因 R4 报告改变而更新；原来经另一邻居的路由若经 R4 更短则改用 R4。投影中的完整数字表没有进入转写，因此讲义不构造貌似原题的完整答案表。

第二组例子由邻居 C 发来更新（47:32–49:51）。本地经 A 到达的某网络与 C 的更新无关，保持原状；经 C 的路由要随 C 的新宣告调整；原表缺少的路由可新增；原经 F 度量 8，改经 C 候选度量 5，则选择 C。课堂还说明等度量时保留原路线，原路线更短时也保持；RIP 只按跳数比较，即使另一条光纤路径带宽更高、当前跳数却更长，按本题 RIP 度量仍不会因此选它（48:51–49:49）。

补充独立算例：R 原表为 `A: 经 X, 3`、`B: 经 Y, 4`、`C: 经 Z, 6`。X 新宣告自己到 A 为 4 跳、到 B 为 2 跳、到 D 为 3 跳。R 计算候选为 A 经 X 5、B 经 X 3、D 经 X 4。于是 A 更新为 5，因为原来依赖 X；B 改为经 X 3，因为优于经 Y 4；D 新增经 X 4；C 保持经 Z 6，因为与 X 的新信息无关。检查时逐个目标写“原下一跳、候选下一跳、原距离、候选距离”，能避免只比较数字而忽略原路径是否依赖 X。

### 把更新规则写成可检查的计算过程

补充说明：课堂使用的目标网络、距离和下一跳三列，可以逐行处理。设当前路由器为 R，收到邻居 X 的信息 `N, d_X`，候选距离记为 $d'=\min(16,d_X+1)$，候选下一跳为 X。这里的 16 是 RIP 所用的不可达度量；若 X 已报告 16，经 X 的候选仍写 16。R 的原记录若是 `(N,d_R,Y)`，需要同时比较 $d_R$ 与 $d'$，还要比较 Y 与 X。这是距离相同却有不同处理结论的根本原因。

如果 Y 就是 X，原记录依赖这个邻居，邻居新报告变差时，R 不能继续保留原距离。比如原值为 `(N,3,X)`，X 现在报告到 N 为 6，R 经 X 的候选是 7；继续保留 3 等于相信一份已经被 X 更新的信息。若 Y 是另一邻居，而 X 给出的候选 7 大于原值 3，原路径仍可保留。把这两种情况都简化成“只选较小数字”，就会把失效路径当成可用路径。

若一份题目只展示邻居的部分更新，还须确认题目有没有声明“本次消息包含邻居的完整路由表”。对于部分更新，未出现某目标不代表 X 已撤销这个目标；对于完整更新，原先只经 X 才可达的目标从更新中消失，才需要结合课堂规则处理。实际 RIP 的定时器与路由失效处理更完整，课堂计算题应遵循题干给出的状态与更新条件。此处的限定也解释了为什么教师在 39:41–43:52 逐项讨论原表、新表和下一跳。

### 可重复练习的第二个算例

补充说明：R 的原表有 `P: 2, 经 A`、`Q: 5, 经 B`、`S: 4, 经 C`。收到 B 的完整更新：`P: 2`、`Q: 6`、`T: 1`。先统一加 1，得到经 B 的候选 `P: 3`、`Q: 7`、`T: 2`。P 原经 A 且 2 小于 3，保留；Q 原经 B，更新为 7；T 原表不存在，新增经 B、距离 2；S 原经 C，保持原值。计算表如下：

| 目标 | 原值 | B 的报告 | 经 B 的候选 | 结果与依据 |
| --- | --- | --- | --- | --- |
| P | 2，经 A | 2 | 3，经 B | 仍为 2，经 A；原路径更短 |
| Q | 5，经 B | 6 | 7，经 B | 改为 7，经 B；原路径依赖 B |
| S | 4，经 C | 未列出 | 无候选 | 仍为 4，经 C；原路径与 B 无关 |
| T | 无 | 1 | 2，经 B | 新增 2，经 B |

再设 B 报告到 Q 的度量变成 16，R 对 Q 的候选也应按不可达处理；不要写成 17 条可用距离。R 可能通过其他邻居重新学习 Q，但必须有相应更新证据。若题目要求写最终路由表，应把未变化的 P、S 一并列入，避免只交发生变化的两行。对每行注明“新建、更新、保留、失效”的原因，既能检查数值，也能检查下一跳。

**【考试要求】教师明确要求会做 RIP 路由表更新题，并说考试很容易出现这种题型。**（49:51–50:19）关键是先给邻居通告距离加 1，再判断目标是否存在、原下一跳是否同一个邻居、候选距离是否更短。等距离如何处理按课堂例题规则写出；完整真实协议还有更多计时器与防环行为，本节计算题主要采用教师展示的更新规则。
