## 蜂窝移动通信的发展与覆盖（00:49–12:45）

蜂窝网络将较大的服务区域划分成多个小区，由基站提供无线接入，并通过网络核心部分连接其他用户与数据网络。移动设备在不同小区间切换时，网络需跟踪用户位置并将通信转送到当前服务区域。无线接入技术在覆盖范围、速率、移动性、频谱效率和基础设施成本之间作取舍。

课堂按发展代际作历史性介绍：第一代以模拟语音为主；第二代开始提供数字语音和短信，GSM 是代表性系统；GPRS 常称 2.5G，EDGE 属于后续增强阶段；第三代标准包括 CDMA2000、WCDMA 和 TD-SCDMA，采用电路交换与分组交换共存的体系，语音与数据路径有所不同（01:42–04:53）。第三代移动通信规范以 IMT-2000 为代表，课堂比较固定与移动状态下的数据率，说明移动速度提高时链路速率与维持通信的能力会受到限制。

此处代际与速率是课程介绍的历史背景，具体实现和运营网络会随频谱分配、标准版本与地区而不同。复习时重点理解蜂窝接入的移动性、切换和覆盖层级，避免将某一代际的理论峰值当作当前设备的实际应用速率。

蜂窝系统通过基站覆盖较大区域；Wi-Fi 的 AP 覆盖较小，WPAN 范围更短。宏蜂窝和微蜂窝等部署方式可根据用户密度与覆盖需求调整小区大小。小区变小能提升局部容量，但需要更多基站和更复杂的切换管理。

## Mobile IP 要解决的问题（12:45–14:24）

普通 IP 主机移动到另一个网络后，通常会获得新网络的地址。若正在进行 TCP 连接，通信端点地址发生变化可能导致原连接无法继续。Mobile IP 希望移动用户离开归属网络后，仍使用稳定的永久地址，使上层应用尽量不感知用户位置变化（12:45–14:24）。

举例而言，主机在校园网中获得地址后，正在通过 TCP 传输文件。若它移动到校外并接入不同网络，新的接入网络会提供不同 IP 地址；对端若继续向旧地址发送数据，数据仍会被路由到原归属网络。Mobile IP 借助代理和隧道，让网络把发往永久地址的数据转交到移动节点当前所在网络。

## Mobile IP 中的地址和代理（14:26–16:14）

移动节点归属网络中的稳定地址称为永久地址（home address）。归属网络中的归属代理（Home Agent, HA）代表移动节点接收发往永久地址的数据。移动节点漫游到外地网络后，可由外地代理（Foreign Agent, FA）提供转交地址（Care-of Address, CoA），标识移动节点当前的接入位置（14:26–16:14）。

移动节点向 HA 登记当前 CoA。HA 保存“永久地址对应当前 CoA”的映射。发送方仍使用永久地址作为目的地址，不必预先知道移动节点已经漫游。HA 收到发往移动节点永久地址的数据后，将原始数据报封装在新的数据报中，外层目的地址设为 CoA，并经隧道送往 FA。FA 解封装后，根据已登记的链路层信息把内层数据交给移动节点。

| 名称 | 作用 | 稳定性 |
| --- | --- | --- |
| 永久地址 `home address` | 上层通信持续识别移动节点 | 移动期间保持不变 |
| 归属代理 `HA` | 维护移动节点位置并截获发往永久地址的数据 | 位于归属网络 |
| 转交地址 `CoA` | 标识移动节点当前外地网络位置 | 随漫游位置更新 |
| 外地代理 `FA` | 为到达 CoA 的封装数据解封并交给移动节点 | 位于被访网络 |

## Mobile IP 的上行与下行数据路径（16:18–20:50）

通信者 A 向移动节点 B 发送时，若 B 已漫游，其永久地址仍指向归属网络。数据先被路由到 B 的归属网络，由 HA 截获；HA 再隧道封装至 CoA 所在的 FA；FA 解封装并在本地链路上交付给 B（16:18–19:56）。因此下行方向经由“通信者 → HA → FA → 移动节点”。

移动节点向通信者发送时，可以继续以永久地址作为源地址，路由器依据目的通信者地址直接转发到对端，无须先绕回 HA。于是上行与下行路径可能不同。最后一跳在外地网络内部依据本地链路地址交付；虽然内层 IP 目的地址仍是永久地址，链路层仍能使用 FA 维护的本地信息送到实际移动节点（19:38–20:47）。

隧道通过外层 IP 首部承载原始 IP 数据报。外层地址用于把数据送到当前 CoA，内层数据报保留原始通信端点地址。FA 解封装后继续按内层目的地址处理。这种封装使原通信端点保持稳定，但增加了额外首部开销，并依赖 HA、FA 间的登记与转发状态。

## 注册、隧道及三角路由（20:50–26:04）

Mobile IP 要求移动节点和 FA 获取 CoA，FA 与 HA 进行登记，HA 封装并转发数据，FA 解封装后继续交付（20:50–22:49）。移动网络层需要相应协议支持，普通路由转发本身不能自动提供这种永久地址到当前接入位置的映射。

三角路由指下行数据绕经 HA 到达移动节点，而移动节点的上行数据可能直接送往通信者。路径呈现“通信者 → HA → 移动节点”和“移动节点 → 通信者”两个方向，形成非对称路径。若通信者与移动节点已经位于同一外地网络，下行数据仍绕到远端 HA 再回来，路径尤其低效（22:49–24:02）。

课堂讨论过引入通信代理或锚定代理缓存移动节点位置，以减少重复绕经归属网络的路径。此方法需要新增位置查询、代理之间的更新和移动状态同步；移动节点继续漫游时，代理信息也要更新。因此路径优化可降低某些场景的绕行，但会增加网络状态和控制复杂度（24:03–26:04）。

蜂窝网络也需跟踪用户位置。通信者通常先联系用户归属网络或位置数据库，查询用户当前服务区，再通过网络核心和基站找到移动用户；这类间接路由依据 IP 或网络层地址寻址，最后一跳再依据链路层地址交付（26:09–27:03）。

## 应用层客户机/服务器与 DNS 引入（31:57–36:30）

网络应用由进程间通信实现。许多 Internet 应用采用客户机/服务器模式：客户机发起请求，服务器提供服务并回应（32:04–32:30）。DNS 将便于人识别的域名解析到 IP 地址，用户通常通过浏览器或应用间接使用这一系统。

域名与 IP 地址之间并非一对一关系。同一 IP 可承载多个服务名称，例如邮件、Web 或文件服务分别使用不同域名；一个域名也可能对应多个 IP，以支持镜像、负载分担或多地点部署（32:51–34:17）。域名中的点号表示层级分隔，与 IPv4 地址点分十进制中的分隔作用不同，也不表示实际地理位置。

域名层级从根开始，包含顶级域、二级域及更多下级名称。顶级域可按国别、通用用途或基础设施功能区分；例如 `.cn` 属于国别域，`.com` 等属于通用域。反向解析使用专门的域名空间，将地址映射回名称。每级名称由相应管理方委派，层级结构支持分布式管理。

### 域名层级如何分工

域名末尾的根以空标签表示，书写时通常省略；其下是顶级域，再向左增加更具体的子域标签。比如 `www.example.com` 可以从右向左读出根、`com`、`example`、`www` 这几层。用户常省略结尾的根点，DNS 查询仍在根开始逐层寻找。名称层次表示命名管理边界，不直接说明主机的物理位置，也不保证一个标签对应一台服务器。

不同组织可以管理不同层次。根区提供顶级域委派资料，顶级域管理者维护二级域委派，具体域的管理者维护自己的主机和服务记录。父级只需要知道下一层由谁负责，无须保存整个互联网全部主机名。层级委派将维护工作分布到不同管理单位，也让查询能由较粗略线索逐步收敛到具体答案。

DNS 名称与地址的对应关系可以是一对多或多对一。一个名称可能配置多个地址，以便分担请求、选择不同服务节点或在服务器不可用时提供其他目的地；一个地址也可承载多个名称和服务。因而名称查询不是简单地把每个域名永久绑定到唯一机器。访问某个服务时，DNS 记录给出的是当前配置下可用的资源信息，服务的实际选择还可能受缓存、调度和应用配置影响。

### 正向解析与反向解析

正向解析从域名取得 IP 地址，常用于浏览器访问服务前定位服务器。反向解析从 IP 地址查询名称，使用专门的反向域名空间；IPv4 地址通常映射到 `in-addr.arpa` 下的名称，IPv6 地址使用 `ip6.arpa`。反向查询记录由地址空间管理方维护，不一定能得到与正向解析完全对应的名称。因此，正向解析成功不能推断反向解析必然成功，反向解析结果也不能替代应用实际连接时的正向解析。

### DNS 资源记录与查询结果（补充说明）

课堂本节介绍域名、区域以及本地服务器、根服务器和权威服务器的关系，没有逐项讲授资源记录格式。以下内容是用于理解 DNS 答案结构的补充说明，属于通用 DNS 知识。

DNS 返回的数据以资源记录为基本单位。记录包含名称、类型、类别、有效期限及记录值等信息。地址记录可用于返回 IPv4 或 IPv6 地址；名称服务器记录指出某个区域的权威服务器；邮件交换记录指出接收邮件的服务器。以上字段的作用用于解释为什么 DNS 查询返回的不总是一个数字地址。

查询某个名字时，服务器可能返回最终资源记录，也可能返回下一层服务器的委派线索，还可能说明名称不存在或暂时无法提供答案。客户端或递归解析器必须根据响应类型决定是否结束查询。理解“服务器回答了”与“得到最终地址”之间的区别，有助于解释为何解析过程需要多轮请求。

### DNS 查询过程的逐步例子

以下查询步骤依据本节讲授的层级关系整理；递归解析器和委派应答的细节属于补充说明。

假设主机需要访问 `www.example.com`，但本地没有有效缓存。主机先把问题交给配置的本地 DNS；本地 DNS 查询根服务器，取得 `.com` 顶级域服务器线索；接着向 `.com` 服务器询问 `example.com`，得到该区域权威服务器的地址；最后查询权威服务器并取得主机记录。结果返回本地 DNS 后，本地 DNS 再将地址交给主机。若任何一层的有效缓存已经存在，查询可以从该层直接取得相应资料，减少后续往返。

在这条流程中，主机通常只需等待本地 DNS 给出结果。它并不需要自己保存根、顶级域和权威服务器列表并逐一查询。递归解析器承担继续追问的工作，层级服务器则根据本级管理范围回答最终记录或委派信息。描述查询流程时，写清“谁发问、问哪一级、收到最终记录还是下一步线索”比只背服务器名称更准确。

### 缓存、有效期限与变更可见时间

本小节属于补充说明：本节字幕没有展开 DNS 缓存期限和缓存排查。

缓存记录附带有效期限。有效期限尚未结束时，解析器可以复用记录；期限到达后，解析器需要重新向有权威性的服务器查询。有效期限过长可减少重复查询和响应时间，但配置变更后旧资料可能保留更久；期限较短可让更新较快被重新查询，同时增加 DNS 查询负载。名称服务的变更可见时间因此与缓存有效期有关，并非所有用户在同一时刻同时取得更新。

如果不同用户报告某域名对应地址不同，排查时可以依次比较权威区中的记录、本地递归解析器缓存、终端缓存和查询时间。记录刚变更时，各级缓存剩余有效期可能不同。不能只依据一台主机的一次查询就认定权威记录错误，也不能因缓存存在就认为记录会永久保持旧值。

### 区域、授权与冗余

区域划分和权威服务器与本节讲授内容相关；主辅服务器同步机制属于补充说明。

DNS 名称空间是树状的，管理资料可以划分为若干区域（zone）。一个区域保存由其权威服务器负责的名称记录；更下层子域可以作为单独区域委派出去。域名树的层级与区域边界相关，但并非每一个标签都必须单独对应一个区域。委派让父区域只需记录下级区域的服务器信息，子区域管理者再独立维护其内部资料。

主、辅 DNS 服务器可以保存同一区域的资料副本，提供冗余服务。当单台服务器故障时，其他服务器仍可应答；但副本需要通过区域传送或相应更新机制保持一致。冗余提升可用性，缓存减少重复查询，二者解决不同问题。若权威服务器数据尚未同步，冗余节点也可能短时给出不同结果，故排查要核对具体应答服务器及其资料版本。

### 逻辑根服务器与实际部署

课堂提到逻辑根服务器标识与全球分布式部署；任播及具体部署作用属于补充说明。

课堂指出根服务器名称数量是 13 个，全球访问通过分布式镜像节点承载。这里应把逻辑标识与机器数量区分：根服务器的逻辑名称集合用于提供根区域服务，实际部署可由大量分布在不同地点的实例响应查询。任播允许多个地点公布同一服务地址，由路由把查询送往较合适的实例。用户查询根服务器时，不必理解为请求固定送往某一台位于单一地点的机器。

分布部署可缩短部分查询的网络距离，并分担流量；逻辑层级则维持统一的 DNS 委派关系。两者分别回答“名称服务如何组织”和“服务实例如何在网络中提供”这两个问题。不要把根服务器逻辑标识数直接理解为全球可响应查询的实体总数。

### Mobile IP 注册与转交过程的状态变化

把移动节点接入新网络后的过程按状态追踪，可以看清 HA 为什么能够继续接收发往永久地址的数据。首先，移动节点发现当前接入网络，并从 FA 或当前网络取得 CoA；其次，移动节点向 HA 登记该 CoA，HA 更新永久地址与当前转交位置的对应关系；随后，通信者仍将数据发往永久地址，普通 IP 路由把分组送到该地址所属的归属网络；最后，HA 查到最新登记，将原始 IP 分组封装并通过隧道送到 CoA。FA 收到后移除外层首部，再把内层分组交给移动节点（14:26–22:49）。

位置绑定需要随着移动节点再次迁移而更新。若节点离开旧网络后仍使用旧 CoA，HA 就会继续把封装分组送往旧位置；新网络取得新 CoA 并完成登记后，HA 才能按新的映射转交数据。由此可见，永久地址稳定并不代表底层位置无需管理。节点发现新接入点、取得可路由的转交地址以及更新 HA 状态，是维持通信连续性的必要环节。

### 隧道封装中的内层和外层地址

设通信者 C 向移动节点 M 发送一个 IP 数据报。初始数据报的目的地址是 M 的永久地址；该内层数据报首先按永久地址路由到 HA。HA 隧道封装时保留内层源、目的地址，并增加外层 IP 首部；外层目的地址使用当前 CoA，使普通网络能够将隧道数据送至移动节点当前所在处。隧道终点去掉外层首部后，内层目的地址仍是永久地址，移动节点的上层连接因而继续使用原通信身份。

检查图示时，应把两层首部分别列出。内层源地址是通信者地址，内层目的地址是移动节点的永久地址；外层源地址是 HA 所在端的隧道地址，外层目的地址是 CoA。途中路由器仅依外层目的地址把封装数据转发到隧道终点。题目若只问最终 IP 目的地址，应说明它指的是解封装后的内层目的地址；若问隧道路由目的，则填写外层 CoA。

封装会增加额外首部，因此同一底层链路可承载的有效数据比例会下降。若路径 MTU 不变，新增首部也会减少隧道中内层分组可以携带的数据量；超过承载上限可能需要分片或调整发送端报文大小。课堂侧重地址保持和转发路径，并未要求计算具体封装首部长度，涉及数值时应以题目给出的隧道协议为准。

### 三角路由的路径比较

假设移动节点从归属网络移至外地网络，通信者仍在归属网络附近。通信者发出的数据先到 HA，再由 HA 经隧道回到移动节点附近；移动节点上行则可能直接送回通信者。与两端都按当前拓扑直接通信相比，下行绕行增加了路径长度，形成三角路由。若通信者也在远处，HA 绕行带来的额外距离可能较小；因此是否明显低效取决于通信者、HA 和 CoA 的相对位置。

从路径角度比较时，可列出两条方向：下行 `通信者 → 归属网络中的 HA → 隧道 → CoA 所在网络 → 移动节点`；上行 `移动节点 → 通信者`。路径不对称会使两个方向时延不同，也令故障定位复杂。若采用代理或锚定节点优化，需先取得移动节点的当前位置并维护相应映射；移动节点继续迁移时，缓存状态必须更新。优化路径能减少绕行，但增加了位置状态和控制交互，本节只讨论其基本动机（22:49–26:04）。

### Mobile IP 与蜂窝位置管理的联系

蜂窝系统与 Mobile IP 都需回答“用户当前在哪里”，但其管理对象和转发机制不同。蜂窝系统通过基站覆盖和核心网中的位置资料管理移动用户；Mobile IP 课堂模型通过永久地址、HA、FA、CoA 和隧道封装处理 IP 网络间移动。前者包含移动接入与蜂窝核心网络，后者重点在 IP 层对通信地址和当前位置的分离。比较时应指出两者都需要位置更新，之后再分别写出对应网络实体和转发过程（26:09–27:03）。

### 将 DNS 查找与应用连接分开追踪

用户输入域名后，浏览器或应用通常先取得相应地址，之后再与目标服务建立运输层连接。DNS 负责名称查询，应用协议负责访问服务内容；两者是前后衔接的独立过程。即使 DNS 已返回地址，后续服务器仍可能不可达；即使原连接仍可用，缓存中的名称记录也可能已过期。判断故障时，应分别确认名称解析结果、目标 IP 连通性、运输层连接以及应用服务器响应。

在域名查询中，本地 DNS 可能直接用缓存回答，也可能通过根、顶级域和权威服务器逐级取得记录。应用随后使用返回的 IP 地址联系服务器。若一个域名配置多个地址，客户端或解析服务可能返回不同地址；若多个服务共用同一 IP，应用仍可依据名称及其后续协议字段选择目标服务。课堂关于域名和地址关系的例子说明，DNS 返回地址并未取代应用层对服务类型和资源名称的表达（32:51–34:17）。
